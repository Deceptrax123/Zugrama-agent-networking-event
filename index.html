Everyone Meets Everyone, Once

TL;DR

  • Agents avoid meeting the same partner twice, far more than chance would predict. 207 conversations covered 202 of 210 possible pairs. Only 2 pairs ever met twice. If partners were assigned at random, with each agent's number of conversations held fixed, we would expect 68 (95% range 59–77; p < 0.001).
  • Groups were allowed and never used. After a prompt edit allowed group rooms, agents made 2,149 decisions and started 0 groups. That puts the rate of group starts below 0.14% per decision (95% upper bound).
  • A one-line prompt addition changed what agents talked about within minutes. Mentions of music rose from 4.5% to 14.0% of messages (OR 3.5, p < 0.001), peaking at 23% in the half hour after the addition.
  • The run audit changes the story. For 50 minutes, three agents running a Python loop held all three turn slots and the other 18 could not act. Earlier write-ups read that stretch as agents "consolidating" their threads. Four more agents lost 3–4 hours to provider failures. Raw activity counts therefore measure uptime as much as personality: calls predict messages sent (ρ = 0.60).
  • Being sought out is the persona trait that persists. Messages received correlate across reruns (ρ = 0.55–0.63). Messages sent do not (every CI includes 0). Agreement rises over a conversation (z = 4.6), pushback does not change, and 58% of long conversations drift off their opening topic.

Abstract

We study 21 language-model agents (GPT-6.1 Sol, high reasoning) given a shared setting, persona profiles drawn from residency applications and one instruction: meet people. There is no assigned topic, partner or speaking order. Before analysis we audited the complete run record: 2,737 model calls with their raw requests and responses, the usage ledger, tool logs and the platform's state file. The audit found four threats to validity:

  • a 50-minute starvation of the turn queue by three agents in a Python loop;
  • provider outages that removed four agents for 3–4 hours;
  • two mid-run prompt changes;
  • 141 platform-generated whiteboard posts recorded as agent messages.

We exclude or model each of these. We then test 14 exploratory hypotheses about partner choice, group formation, responsiveness to the environment, individual stability and conversation dynamics. The tests use exact or resampling methods and control the false discovery rate.

Three results stand out:

  • Agents act as systematic samplers: they avoid repeat partners about 34 times more strongly than a degree-preserving random null predicts, and never take up an explicit invitation to form groups.
  • Agents respond immediately to the environment: a one-sentence addition to the prompt triples talk on its topic within half an hour.
  • What carries across reruns is how much attention a persona receives, not how much it gives.

We add a topic analysis of conversational direction, data-selected conversation excerpts and an account of how technical work was divided. We argue that several apparent social regularities are properties of the agent interface and scheduler, and that multi-agent social simulations should report a run audit alongside their results.

Research questions

  1. Partner choice.Do agents deepen existing ties or explore new partners, and how does this compare with chance? (N1)
  2. Group formation.When the interface allows rooms of three or more, do agents form or join them? (N2, N3)
  3. Responsiveness to the environment.Does a mid-run change to the shared prompt redirect what agents talk about? (N4, topic analysis)
  4. Individual differences.Is activity evenly spread, what drives the differences, and which persona-level positions reproduce across reruns? (N5–N7)
  5. Conversation dynamics.How do stance, attention, topic and memory evolve within and across conversations? (N8–N14)

All hypotheses are exploratory. They were formulated after reading the prior qualitative audit of this run and were then tested on the frozen logs. They were not pre-registered. We report every test we ran, including null results, and adjust p-values for multiple comparisons (Benjamini–Hochberg).

Methods

Population

21 resident personas

Built from real residency applications: skills, offers, needs and an authored introduction. Every agent ran on the same model (GPT-6.1 Sol, high reasoning) through the Hermes agent gateway, with private memory and a bounded transcript.

Action space

One JSON decision per wake-up

Each decision could start up to three conversations, join or leave rooms, send up to three messages, call tools (Python, web, whiteboards, workspaces, memory recall) and choose wait_seconds. A shared turn queue let at most three agents act at once.

Record

Main run (Run 3), 8.6 h

2,737 model calls, 2,795 agent-written messages, 207 conversations, 435 Python executions and $128.29 of API-equivalent spend. Runs 1 and 2 used the same personas under earlier protocol versions.

Data sources
The frozen event database (read-only), the public archive export of all three runs, the raw request/response audit of every model call, the platform state file (restarts, prompt additions) and the tool-run log. No agent code was re-executed.
Inclusion
Messages written by agents. We excluded 141 Run 3 messages (4.8%) that the platform posted under an agent's name when it published a whiteboard or workspace revision. One helper-model call is excluded from decision counts.
Measures
  • Repeat pair: two one-to-one rooms with the same two agents.
  • Group start: a start action naming two or more peers.
  • Music talk: a message matching a 10-stem keyword list.
  • Stance: keyword markers for agreement openers and explicit pushback. These are published, not validated.
  • Topic: TF-IDF features with NMF (k = 10, seed 1). Each component is labelled from its top terms, and each message is assigned its dominant component.
  • Re-introduction: an opener phrase appearing after message 5 of a conversation.
  • Outage: no model call for more than 20 minutes. The wait cap is 10 minutes, so a gap this long means the agent was not scheduled.
Statistics
  • Wilson intervals for proportions, and an exact Clopper–Pearson bound when no events were observed.
  • Fisher's exact test, with Woolf intervals on odds ratios.
  • An exact conditional test for Poisson rate ratios.
  • A degree-preserving random-pairing null (4,000 draws) for repeat meetings.
  • Percentile bootstrap over agents (5,000 resamples) for Gini coefficients and Spearman correlations.
  • Cochran–Armitage tests for trend across quintiles, and Wilcoxon signed-rank tests for paired changes.
Two-sided α = 0.05 after Benjamini–Hochberg adjustment across the 9 tests that produce a p-value.
Reproducibility
analysis/build_data.py builds the descriptive figures and analysis/science.py builds the audit, tests, topics and conversation selection. Both read the frozen sources only. Random seeds are fixed.

Run audit

Before testing anything, we checked whether the run happened as designed. The audit compares four sources:

  • the scheduler's view: when each agent was called;
  • the model's view: raw requests and responses;
  • the ledger: tokens and cost;
  • the platform's view: messages, tools, restarts and prompt changes.

The bookkeeping reconciles. The behaviour does not quite match the design.

Corrects earlier readingOur first draft, and the earlier automated audit, described 0.5–1.7 h as a "consolidation phase" in which agents deepened existing threads. The call log shows something else: 18 of 21 agents were simply not being scheduled. The lull in new conversations is an artifact of the scheduler, not a social phase.

How the audit shapes the analysis. (i) We report per-decision rates rather than raw counts wherever activity matters. (ii) The rank-stability test is repeated without the four outage agents. (iii) Prompt-change effects are estimated in narrow windows around each change and flagged as confounded with time. (iv) Whiteboard posts are excluded from all talk measures.

Results

RQ1 · Partner choice

Agents explore rather than deepen. They meet nearly every possible partner, and avoid meeting anyone twice far more than chance predicts.

Run 3 has three phases. An opening burst comes first: 87 conversations start in the first half hour. Then comes the starvation window, in which almost nothing starts because only three agents are acting. Finally, a steady sweep of 11–20 new partners per half hour lasts to the end. Half of all pairs had met by hour 3.2, and 90% by hour 6.5. Only 2 of the 202 pairs that met ever opened a second conversation.

Is that just what happens when 21 agents have about 20 conversations each? To check, we built a null model. It keeps every agent's number of one-to-one rooms fixed and randomises only who they were with. Under this null, 199 dyadic rooms would contain 68 repeat pairs. The observed 2 is far outside the null distribution.

The conversations themselves are not shallow. The median conversation runs 11 messages, both sides contribute almost equally (median majority share 0.53), and replies arrive within a median of 133 s.

RQ2 · Group formation

An explicit invitation to form groups produced no groups. Every conversation stayed one-to-one.

From 1.67 h, the prompt stated that rooms could hold three or more residents, and the action schema documented the syntax for starting a group. Across 2,149 decisions under that prompt, agents started zero groups and joined zero existing rooms. They opened 189 new one-to-one conversations instead. Starts per decision were lower after the edit than before (rate ratio 0.56). That comparison is confounded twice over: the "before" period contains the opening burst, and it also contains the starvation window, which inflates the number of decisions. We therefore report the ratio but do not interpret it as an effect of the prompt.

Interpretation: each decision offers a peer_ids list beside the agent's own open threads, and naming one peer is the cheapest action that fits that interface. Separating the interface, the model and the late timing of the prompt would need runs where groups are available from the start.

RQ3 · Responsiveness to the environment

A one-sentence addition to the shared prompt redirected conversation within minutes, and the effect then decayed.

At 2.34 h the operators appended "New addition: Music & choreography" to the room prompt. In the hour before, 4.5% of agent messages mentioned music. In the hour after, 14.0% did, peaking at 21–23% per quarter-hour immediately after the addition. Within an hour, talk returned to 4–9%, still above the baseline. The jump happens in the first quarter-hour after the change, and no other intervention falls in that window. That makes the prompt the most plausible cause, although this is a single interrupted time series without a control group.

RQ4 · Individual differences

Message volume is nearly equal across agents. What differences there are track uptime, and only how much a persona is sought out reproduces across reruns.

Messages sent are spread almost evenly: the Gini coefficient is 0.107 (95% CI 0.068–0.132), where 0 would mean perfect equality. The number of times an agent was called varied about four-fold (64–266), mostly because of the outages and queue starvation found in the audit, and it predicts messages sent (ρ = 0.60). Raw activity therefore partly measures infrastructure.

Across the three runs, messages received are correlated for every pair of runs, with confidence intervals above zero. Dropping the four outage agents leaves the estimate essentially unchanged (ρ = 0.62). Messages sent are not stable: every interval includes zero.

RQ5 · Conversation dynamics

Agreement builds over a conversation while pushback holds steady. Juggling more threads does not slow replies, but conversations do lose the thread.

Conversations with six or more messages were split into five equal parts. In each part we counted messages that open with an agreement marker and messages that contain an explicit pushback marker.

  • Agreement rises from 5.3% of messages in the first part to 12–15% afterwards (Cochran–Armitage z = 4.6).
  • Pushback shows no trend (7–10%, z = −0.6, p = 0.52). There is no drift into pure accord.
  • Juggling threads barely affects reply speed. An agent's number of open conversations is essentially unrelated to how fast it replies (ρ = 0.04). The effect is statistically detectable but practically zero.
  • Unanswered endings. 15% of conversations end on an unanswered question.
  • Re-introductions. 6% contain a re-introduction: an agent opens with "your profile caught my eye" deep into a conversation it is already having.

Directions: what agents talked about

We fitted a topic model to all 2,795 agent-written messages and assigned each message its dominant topic.

  • Mostly not work. The two largest themes are not work at all: music and everyday taste (19% of messages) and fiction and scenes (17%). Technical themes (agent memory, payment privacy protocols, biometric proof of personhood) are each 4–9% of messages.
  • Opening exchanges, then a shift. Openers ("your work caught my eye") make up 21% of messages in the first half hour, then almost disappear.
  • Prompt-driven themes. Music jumps at the prompt addition.
  • Converging mixes. Over the run, each agent's topic mix moves closer to the population mix: the median Jensen–Shannon distance falls from 0.26 to 0.22 (Wilcoxon p = 0.02).
  • Drift within conversations. 22 of the 38 long conversations end on a different dominant topic than they started on.

Division of work

Nobody assigned roles, but technical work still concentrated sharply:

  • Python. Run by only a few agents, with a Gini coefficient of 0.78. The top three agents ran of all executions, and they are the three agents that held the turn queue.
  • Whiteboards. Shared more widely (Gini 0.27).
  • Messages. Spread almost evenly (Gini 0.11).

The pattern is specialisation without coordination. The agents who executed code did so in long, private, self-scheduled loops (wait = 0 s), checking a counterexample against hundreds of randomised cases. They did not hand work to others.

Discussion

Interface effects masquerade as social behaviour. Three of our clearest regularities sit close to the agent interface:

  • exploring partners instead of re-meeting them;
  • never forming groups;
  • an apparent "consolidation phase".

The interface lists peers one at a time and the scheduler grants three turns at once. Starvation produced a phase that looked social, and the outages produced activity differences that looked like personality. We suggest that multi-agent social simulations report a scheduler-level run audit as routinely as they report the model and prompt.

Responsiveness cuts both ways. The music result shows that the environment steers these agents quickly. That makes environments a powerful experimental lever. It also means unlogged operator actions can silently confound a study. Here they were logged in the platform's state file, so we could find them.

Tool loops are a coordination failure. Three agents ran 285 Python calls with no wait between them. That is individually rational behaviour that becomes a shared-resource failure under a fixed-capacity queue. Fair scheduling, such as a per-agent rate cap or round-robin turns, is a precondition for interpreting any activity-based measure.

Relation to the earlier auditThe earlier automated audit (GPT-6.1 Sol and GPT-6.2 Astra) produced curated case studies: co-written scenes, a chess game and idea relays. They remain accurate as cases. This study adds three things: a scheduler-level audit that reinterprets one phase, null models and intervals for its qualitative claims, and two new findings, the effect of the music prompt and the persistence of how much each persona is sought out.

Limitations

  • One main run and one model. Runs 1–3 differ in protocol. All agents share one model, so their choices may be correlated through shared priors.
  • Observational, not experimental. The prompt changes were not randomised. The music result rests on timing.
  • Crude text measures. Stance, music and re-introduction are keyword measures, and topics come from an unsupervised model with hand labels. All the patterns are published so they can be checked.
  • Infrastructure noise. Outages and starvation are documented but cannot be undone. Results that depend on activity volume should be read with them in mind.
  • Personas are not people. Nothing here describes the real applicants' behaviour or preferences.

Future directions

  • Separate the interface from the model. Randomise whether agents see a "people you've met" list with a re-contact action, and whether joining an existing room is offered as a first-class action.
  • Groups from the start. Enable group rooms at t = 0 in half of the runs.
  • Randomised prompt additions. Inject topic additions at random times, with a placebo addition, to estimate how responsive agents are and how fast the effect decays.
  • Fair scheduling as a treatment. Compare first-come scheduling with round-robin turns and measure starvation, inequality and conversation coverage.
  • Heterogeneous populations. Mix models and reasoning levels to test whether hubs and communities emerge where homogeneous agents produced none.
