Everyone Meets Everyone, Once

Dyadic lock-in, flat networks and the attention economics of 21 LLM agents at an open-ended networking event

Srinitish Srinivasan

Agent Network Sandbox · November 2026

Sandbox code Figure data (JSON) Analysis scripts Study 2: Project teams →

TL;DR

  • Agents sweep the room instead of building relationships. In the main run, 96% of all possible pairs held a conversation, and 197 of 202 pairs held exactly one. Nothing in the prompt imposed rotation.
  • Groups were offered and never used. Agents made 2,149 decisions under a prompt that explicitly allowed group rooms. They started 0 groups and joined 0 existing rooms, but opened 189 new one-to-one chats.
  • The network is flat in a way human networks are not. Message volume is close to equal across agents (Gini 0.105), reciprocity is 98.7%, and there is almost no community structure (modularity 0.07).
  • Being sought out is a stable persona trait; being chatty is not. Across three reruns, the number of messages a persona received stays correlated (Spearman ρ 0.53–0.65). The number it sent does not.
  • Conversation is mostly reading. Each decision consumed a median 21.4k prompt tokens to produce 372 output tokens, a 47:1 ratio. The run cost $128 in total.

Abstract

We give 21 language-model agents (GPT-6.1 Sol, high reasoning) a shared setting, persona profiles drawn from real residency applications and one instruction: meet people. There is no assigned topic, partner, project or speaking order. Each agent decides independently whom to approach, what to say, how long to wait and whether to use tools such as Python, shared whiteboards and versioned workspaces. We analyse the complete decision log of the retained main run: 2,736 captured model calls, 2,936 delivered messages, 207 conversations and 435 code executions. We compare it with two earlier runs of the same event.

An earlier automated audit (by GPT-6.1 Sol and GPT-6.2 Astra) documented this record through curated case studies of creative co-writing, a chess game and attributed idea relays. Here we build on that audit with network, temporal and decision-level measurements. Agents behave as systematic samplers of the social graph rather than relationship builders: they meet nearly every possible partner once, never reconvene, never form groups even when explicitly invited to, and sustain about five parallel one-to-one threads each. The resulting network is egalitarian and unclustered. A persona's ability to attract messages reproduces across reruns, but its own activity level does not. We argue that these regularities come from the agent decision interface (one-at-a-time, start-or-reply actions over a bounded context) as much as from the model. They should be treated as design variables in multi-agent social simulations.

Experimental setup

Population

21 resident personas

Built from real residency applications: skills, offers, needs and an authored introduction. Every agent ran on the same model (GPT-6.1 Sol, high reasoning) through the Hermes agent gateway.

Instruction

Open-ended networking

"Choose your own topics, partners, questions, disagreements, ideas and possible collaborations… There is no imposed speaking order or recipient rotation."

Action space

One JSON decision per wake-up

Each decision could start up to three conversations, join or leave rooms, send up to three messages and choose wait_seconds (0–3600). It could also call tools: Python, web search, whiteboards, workspaces, memory recall or a helper.

Memory

Bounded, private

Agents received a bounded transcript, per-peer encounter indexes and retrieved private memory notes. They could only see messages from conversations they had joined.

Change mid-run

Group rooms enabled at 1.67 h

From that point the system prompt added: "Rooms may contain three or more residents; there is no two-person room cap… start a group with several listed residents." 2,149 decisions (79%) were made under this version.

Record

Main run (Run 3), 8.6 h

2,936 messages, 207 populated conversations, 130 whiteboards, 435 Python calls and $128.29 of API-equivalent spend. Runs 1 and 2 used the same personas under earlier protocol versions.

Findings

Finding 1 · Coverage over depth

Agents systematically sample the whole room: nearly every pair meets, and almost none meets twice.

Run 3 has three phases. First comes an opening burst: 87 conversations start in the first half hour and a third of all pairs make contact. Next is a consolidation phase of about 70 minutes. Agents keep deciding at the same rate (137–175 decisions per half hour) but start almost no new conversations (1–6 per half hour). They are deepening the threads they already have. From 1.7 h onward there is a steady sweep of 11–20 new partners per half hour, and it continues until the event ends: half of all pairs had met by hour 3.2 and 90% by hour 6.5. Only 2 of the 202 pairs that met ever opened a second conversation. The conversations are not shallow, though: the median runs 12 messages, and both sides contribute almost equally (median majority share 0.54).

Extends prior auditThe earlier audit noted that agents "chose people and topics" and highlighted hobby conversations. The full graph shows that this choosing follows a regular pattern: work through the directory and don't come back. For a social simulation, that means relationships never get a second encounter in which to build on the first.
Finding 2 · Dyadic lock-in

Agents ignored an explicit invitation to form groups. Every conversation stayed one-to-one.

For the last 80% of the run, the instructions stated that rooms could hold three or more residents, and the action schema documented the syntax for a group start. Across 2,149 decisions under that prompt, the parsed actions contain zero group starts and zero joins of an existing room. Agents opened 189 new one-to-one conversations instead. In fact the start rate rose right after the switch, from 1–6 to 11–20 per half hour: the prompt that invited groups coincided with more dyads. That timing is confounded with first threads winding down, so we don't claim it was caused by the prompt. Over the whole run, only 9 decisions included an explicit "leave". Conversations were left to go dormant rather than closed.

NewThe earlier audit did not test whether the group affordance was used. Every Run 3 room peaked at two residents. A third member appears in a room only when the disclosed facilitator NPC briefly joins. Because the change came mid-run, existing dyadic momentum is a plausible cause. Still, 189 fresh starts under the new prompt, with no group start among them, suggests a strong default: one partner at a time.

Interpretation: in each decision the agent picks from a peer_ids list and its own open threads. Choosing one peer is the cheapest action that fits that interface. Seeing which of three things drives the default (the interface, the model, or the late introduction of groups) would need runs where groups are available from the start.

Finding 3 · Parallel attention

Each agent keeps about five conversations going at once and answers within about two minutes.

We count a conversation as open from its first to its last message. By that measure, the median agent held 5 conversations in parallel through the middle of the event, and some agents held as many as 16. Replies are fast (median 132 s, 90th percentile 378 s). One in five conversations (39 of 207) ends on a question that never got an answer. That is what you would expect from an agent juggling many threads and letting some drop.

Finding 4 · An egalitarian network

With no structural pressure, the agent network becomes flat, reciprocal and unclustered. Each protocol revision made it flatter.

Across the three runs, density rose from 0.49 to 0.95, reciprocity from 45% to 99%, and modularity fell from 0.14 to 0.07. Inequality in messages sent fell to a Gini coefficient of 0.105, which means almost everyone said about the same amount. Human networking events typically produce a heavy-tailed degree distribution with hubs and cliques. These agents produced the opposite.

Finding 5 · What persists across reruns

How much a persona is sought out carries over between runs. How much it talks does not.

The 21 personas are the same in all three runs, so we can ask which individual-level positions reproduce. Messages received are correlated in every pair of runs (ρ = 0.53, 0.56, 0.65; all p < 0.02). Messages sent and number of distinct partners are not stable (ρ between −0.11 and 0.64, with the Run 2–3 comparison near zero). The profile seems to set how interesting other agents find a persona. Its own activity level looks like run-specific noise.

Revises prior framingThe earlier audit declined to pool runs and treated each persona's activity as an outcome of one run. Rank stability is a different question: it doesn't need the runs to be identical. It shows that persona content shapes how others respond to an agent more reliably than it shapes the agent's own output. In Study 2 we find the same pattern across settings: networking activity does not predict project-run activity (ρ = −0.36).
Finding 6 · Stance dynamics

Agreement rises after the opening exchanges, but pushback holds steady. There is no slide into pure sycophancy.

We split each conversation of six or more messages into five equal parts by position. In each part we measured how many messages open with an agreement marker ("Yes", "Exactly", "I love…") and how many contain an explicit pushback marker ("I'm not convinced", "I'd push back", "counterexample"…). Agreement openers roughly double after the first fifth (5.3% → 10–14%). Pushback stays flat at 8–10% all the way through.

Quantifies prior auditThe audit showed selected cases where a critique changed a scene or a game rule. The lexical rates suggest those cases are typical rather than rare: disagreement stays present throughout conversations instead of fading as rapport builds.
Finding 7 · The economics of a decision

Agents spend 98% of their tokens reading context, and they schedule themselves in round numbers.

Each wake-up re-reads the setting, the directory, recent messages, threads and memory: a median of 21,443 prompt tokens to produce 372 output tokens. Over the run that comes to 58.0M input against 1.23M output tokens. Agents chose their own sleep times, and the choices cluster on 0 s (immediate re-wake, 23%), 600 s (22%), 120 s and 900 s. 6.7% of decisions did nothing at all. 38% called a tool, most often conversation recall (690 calls) and Python (437). Python use was highly concentrated: three agents made 86% of the calls.

What the earlier audit found, in context

An earlier automated audit of this record (GPT-6.1 Sol and GPT-6.2 Astra) produced curated, source-linked case studies. We re-read those cases against the measurements above. They are consistent with them, and the measurements show which cases are typical and which are exceptional.

Typical

Hobby conversations need no deliverable

Chess and terrariums, game-design friction, taste. Most of the 207 rooms are of this kind: about 12 balanced messages with one partner, ending without an artifact.

Typical

Critique changes creative drafts

A garden scene was revised after a challenge to its ending, and alternative endings of a duet were kept. This fits the steady 8–10% pushback rate (Fig. 8).

Exceptional

Shared state needs explicit repair

A stale chess move was resent, questioned and corrected through 11 workspace revisions. Only 11 workspace updates or creations happen in the whole run, so persistent shared state was rare.

Exceptional

Ideas relayed with attribution

An objection travelled from one agent through a second to a third, credited to its source, and was accepted. With 197 of 202 pairs meeting only once, relays like this are the only way ideas cross the network.

Concentrated

Peer criticism sharpens technical checks

Counterexamples to protocol toy models were checked over 720 delivery orders. Technical work was concentrated: three agents ran 86% of the Python.

Agrees

Conditional emergence, not unprompted social life

We agree with the audit's framing. The new regularities (sweeping, dyads, flatness) are behaviour within a designed interface, and they say as much about the interface as about the agents.

Limitations

  • One main run, one model. Runs 1–3 differ in protocol, so they are not replications. All agents share one model, so their "independent" choices may be correlated through shared priors.
  • The group prompt came mid-run. Dyadic momentum from the first 1.7 hours could explain part of the zero group uptake. A clean test needs groups from the start.
  • The bounded context shapes behaviour. Agents saw a capped list of threads and recent messages. Sweeping and non-reconvening may reflect what was visible, not a preference.
  • Lexical stance markers are crude. Keyword rates are not validated measures of agreement or sycophancy. We publish the patterns so they can be audited.
  • Personas are not people. The agents represent residency applicants. Nothing here describes the real people's behaviour, relationships or preferences.

Open questions

  • Is the sweep an interface effect? Randomise whether agents see a persistent "people you've met" list with a re-contact affordance.
  • What would unlock groups? Enable groups from t = 0, and compare with a variant where joining an existing room is a first-class action listed beside peer IDs.
  • Can attention be budgeted? Cap concurrent threads at 1, 3 and unlimited, and measure unanswered questions, conversation depth and cost per message.
  • Does heterogeneity create structure? Mix models or reasoning levels and check whether hubs and communities emerge where homogeneous agents produced none.
